Azure App Service — Key Concepts for the Developer Associate

2024-01-18 Azure App Service Azure Developer Associate

Azure App Service is a fully managed PaaS (Platform as a Service) offering for hosting web applications, REST APIs, and mobile backends. It abstracts infrastructure management and lets you focus on application code. For the Azure Developer Associate exam, understanding how App Service works under the hood matters more than just knowing that it exists.

App Service Plans

Every App Service app runs inside an App Service Plan, which defines the region, the number of VM instances, and the pricing tier. The plan is the unit of compute — not the app itself.

Multiple apps can share the same plan and therefore share the same compute resources.

Pricing tiers

  • Free / Shared — shared infrastructure, no SLA, development only
  • Basic — dedicated VMs, manual scaling, no deployment slots
  • Standard — auto-scaling, up to 5 deployment slots, daily backups
  • Premium — more scale-out instances, more slots, VNet integration
  • Isolated — runs in an App Service Environment (ASE), fully private networking

Deployment Slots

Deployment slots are live environments within the same App Service app — for example production and staging. Each slot has its own hostname and can run independently.

The key feature is slot swapping: you swap staging into production with zero downtime. During a swap, App Service warms up the staging slot before routing traffic, so users never hit a cold instance.

Slot settings

  • App settings and connection strings marked as slot-specific stay with the slot and do not follow the swap
  • Settings not marked as slot-specific are swapped along with the code
  • This lets staging point to a staging database while production points to the production database — without changing config after a swap

Scaling

Scale up (vertical)

Move to a higher pricing tier to get more CPU, memory, and features. Requires a plan change.

Scale out (horizontal)

Add more VM instances to handle load. Available from Standard tier upward. Can be configured manually (fixed instance count) or automatically with autoscale rules based on metrics like CPU, memory, or HTTP queue length.

Custom Domains and TLS

  • Custom domains are mapped via CNAME or A records in your DNS provider
  • App Service can manage TLS certificates for you (App Service Managed Certificate — free for apex and subdomains)
  • You can also upload your own certificate or use a certificate stored in Azure Key Vault
  • HTTPS-only enforcement is a one-setting toggle on the app

Authentication and Authorization

App Service has a built-in authentication layer called Easy Auth (also referred to as the App Service Authentication feature). It sits in front of your application code and handles token validation, session management, and identity provider federation.

Supported identity providers

  • Microsoft Entra ID (Azure AD)
  • Google, Facebook, Twitter
  • Any OpenID Connect-compliant provider

With Easy Auth enabled, incoming requests carry the validated identity in HTTP headers (X-MS-CLIENT-PRINCIPAL), so your application code can read claims without handling token validation itself.

Networking

Inbound

  • Access restrictions — IP allow/deny rules at the platform level
  • Private endpoints — expose the app on a private IP inside a VNet (Premium and higher)

Outbound

  • VNet Integration — lets the app make outbound calls to resources inside a VNet
  • Does not give the app a private inbound address, only outbound routing through the VNet

App Settings and Configuration

  • App settings are injected as environment variables at runtime
  • Connection strings follow the same pattern with type-prefixed variable names
  • Settings can reference Azure Key Vault using Key Vault references: @Microsoft.KeyVault(SecretUri=...)
  • The app must have a managed identity with read access to the Key Vault secret

Deployment Options

  • ZIP deploy — push a zip archive via the Kudu API or Azure CLI
  • GitHub Actions / Azure DevOps — CI/CD pipelines with the Azure Web Apps deploy task
  • Container registry — deploy a Docker image directly from ACR or Docker Hub
  • Run from package — mount the deployment package directly without extracting; faster cold starts
