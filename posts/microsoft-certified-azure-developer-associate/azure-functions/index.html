Azure Functions — Triggers, Bindings, and Hosting Plans

2024-02-01 Azure Serverless Azure Developer Associate

Azure Functions is the serverless compute service in Azure. You write event-driven code and Azure manages the underlying infrastructure, scaling, and execution. For the Developer Associate exam, the focus is on how triggers and bindings work, the differences between hosting plans, and when to use Durable Functions.

Triggers and Bindings

Every function has exactly one trigger — the event that causes it to run. Bindings are optional connections to other services that allow the function to read input or write output without writing connection code manually.

Common triggers

  • HTTP trigger — invoked by an HTTP request; used to build APIs and webhooks
  • Timer trigger — runs on a CRON schedule; useful for recurring jobs
  • Blob trigger — fires when a blob is added or updated in Azure Storage
  • Queue trigger — fires when a message is added to an Azure Storage Queue
  • Service Bus trigger — fires on messages in Service Bus queues or topics
  • Event Hub trigger — fires on events in an Event Hub stream
  • Cosmos DB trigger — fires on changes in a Cosmos DB change feed

Input and output bindings

  • Input bindings load data into the function (e.g. read a blob, read a Cosmos DB document)
  • Output bindings write results out (e.g. write to a queue, insert into Cosmos DB, send an email via SendGrid)
  • Bindings are declared in function.json (in-process model) or as attributes/decorators (isolated worker model)

Hosting Plans

The hosting plan controls scaling behaviour, cold start characteristics, and cost.

Consumption plan

  • Scales automatically based on incoming events
  • Scales to zero when idle — you pay only for executions
  • Subject to a cold start when scaled to zero
  • Execution timeout: 5 minutes default, 10 minutes maximum

Premium plan (Elastic Premium)

  • Pre-warmed instances eliminate cold starts
  • VNet integration supported
  • Longer execution timeouts (up to 60 minutes)
  • More powerful instance sizes available
  • Minimum one always-warm instance (billed continuously)

Dedicated (App Service) plan

  • Functions run on the same VMs as App Service apps
  • No cold starts — instances are always running
  • You manage scaling manually or with autoscale rules
  • Useful when you already pay for App Service capacity

Durable Functions

Durable Functions extend Azure Functions with stateful orchestration. They allow you to write long-running workflows as code without managing state, checkpointing, or restarts.

Core patterns

  • Function chaining — execute a sequence of functions in order, passing output to the next
  • Fan-out / fan-in — execute multiple functions in parallel, then aggregate results
  • Async HTTP APIs — start a long job, poll for status using a generated status URL
  • Human interaction — pause the orchestration and wait for an external event (e.g. approval)
  • Monitor — poll a condition at intervals until it becomes true
  • Saga / compensating transactions — coordinate multi-step transactions with rollback on failure

Key components

  • Orchestrator function — defines the workflow using yield / await patterns; must be deterministic
  • Activity function — does the actual work; called by the orchestrator
  • Entity function — manages small pieces of durable state (virtual actors pattern)

Function App Configuration

  • Functions are grouped inside a Function App — this is the deployment and management unit
  • All functions in a Function App share the same plan, storage account, and app settings
  • App settings are injected as environment variables, just like App Service
  • Key Vault references work the same way: @Microsoft.KeyVault(SecretUri=...)

Security

HTTP trigger authorization levels

  • Anonymous — no key required, anyone can call the endpoint
  • Function — a per-function key must be included in the request
  • Admin — the host master key is required

For production APIs, prefer placing the function behind API Management rather than relying on function keys for access control.
