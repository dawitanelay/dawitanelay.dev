Develop for Azure Storage — Blobs, Queues, Tables, and Files

2024-02-15 Azure Storage Azure Developer Associate

Azure Storage is the foundational data storage service in Azure. It covers four distinct storage types — Blob, Queue, Table, and File — each designed for a specific access pattern. The Developer Associate exam tests your understanding of each type, how to secure access, and how to manage data lifecycle and costs.

Storage Account Basics

All Azure storage services are grouped under a storage account. The account type determines what services and redundancy options are available.

  • Standard general-purpose v2 — supports all storage types; recommended for most scenarios
  • Premium block blobs — high-performance SSD-backed storage for low-latency blob workloads
  • Premium file shares — SSD-backed Azure Files for high-throughput file workloads
  • Premium page blobs — used for Azure VM disks

Redundancy options

  • LRS — Locally Redundant Storage, 3 copies in one datacenter
  • ZRS — Zone Redundant Storage, 3 copies across availability zones
  • GRS — Geo Redundant Storage, LRS + async replication to a secondary region
  • GZRS — ZRS in primary region + async replication to secondary
  • Read-access variants (RA-GRS, RA-GZRS) allow reads from the secondary endpoint

Blob Storage

Blob storage is Azure's object store for unstructured data — images, videos, logs, backups, and large data files.

Blob types

  • Block blob — optimized for sequential read/write; used for most files and media
  • Append blob — optimized for append operations; ideal for logging
  • Page blob — optimized for random read/write; used for Azure VM OS and data disks

Access tiers

  • Hot — frequent access; higher storage cost, lower access cost
  • Cool — infrequent access (at least 30 days); lower storage cost, higher access cost
  • Cold — rarely accessed (at least 90 days); even lower storage cost
  • Archive — offline storage (at least 180 days); lowest storage cost, requires rehydration before access

Tiers can be set at the account level (default) or overridden per blob.

Lifecycle management

Lifecycle management policies automatically move blobs between tiers or delete them based on age or last access time. Rules are defined in JSON and applied at the storage account or container level.

  • Example: move to Cool after 30 days of no access, move to Archive after 90 days, delete after 365 days
  • Rules apply to block blobs and append blobs; page blobs are not supported

Shared Access Signatures (SAS)

A SAS token is a URI that grants restricted, time-limited access to a storage resource without exposing the account key.

SAS types

  • Account SAS — grants access to resources across one or more storage services
  • Service SAS — grants access to a specific resource in a single service (blob, queue, table, or file)
  • User delegation SAS — backed by Microsoft Entra ID credentials instead of the account key; most secure option

Always prefer user delegation SAS when possible, as it does not rely on a storage account key and supports revocation via the Entra ID identity.

Queue Storage

Azure Queue Storage provides a simple, durable message queue for asynchronous communication between components. Messages can be up to 64 KB in size and the queue can hold millions of messages.

  • Default message visibility timeout: 30 seconds (configurable)
  • Maximum message TTL: 7 days by default, up to 7 days
  • Messages become invisible while being processed; if not deleted within the timeout, they reappear for retry
  • Use Service Bus for guaranteed ordering, dead-lettering, sessions, or messages larger than 64 KB

Table Storage

Azure Table Storage is a NoSQL key-value store for structured, schema-less data. It is cost-effective for large datasets that do not require complex queries.

  • Data is organized by PartitionKey and RowKey — together they form a unique entity key
  • Queries that include the PartitionKey are fast; cross-partition queries are slower and more expensive
  • For richer query capabilities and global distribution, Azure Cosmos DB for Table is the upgraded alternative

Azure Files

Azure Files provides fully managed cloud file shares accessible via the SMB (Server Message Block) and NFS protocols. This makes it a drop-in replacement for on-premises file servers.

  • Can be mounted on Windows, Linux, and macOS simultaneously
  • Supports Azure File Sync to cache frequently accessed files on-premises
  • Soft delete and snapshots provide data protection and point-in-time recovery
